# Let's Encrypt Certificate Generation (locally-managed)

TUI wizard for **locally-managed** WatchGuard Fireboxes over SSH (default port `4118`).

> **Cloud-managed Firebox?** Use the WatchGuard Cloud beta feature **Let's Encrypt Certificate Generation** (Firebox Cloud Management). This tool is only for **locally-managed** Fireboxes.

## Status: working end-to-end (tested on Fireware 12.12.3)

* Auto-assesses the web server cert on connect: self-signed (Fireware CA) vs valid / expiring / expired, with expiry countdown.
* Issues: openssl key + CSR → `certbot` HTTP-01 (`--standalone` or `--webroot`, staging or production) → `.pfx` bundle with autogenerated 32-char password.
* Imports via Firebox CLI over a temporary built-in TFTP server (PEM files, chain order enforced, demanded root CAs auto-resolved, combined cert+key bundle when the box asks for the key) — or `.pfx` via Web UI/WSM.
* Selects the cert as web server cert (`configure` → `web-server-cert`, with confirmation) and verifies it is active.
* No credentials are stored.

## Requirements (system binaries, no pip deps)

| Binary | Used for | Check |
|---|---|---|
| `python3` | runs `acme.py` (stdlib only) | `python3 --version` |
| `ssh` | PTY session to Firebox port `4118` | `ssh -V` |
| `openssl` | key + CSR (`genrsa`, `req -new`) and `.pfx` bundle (`pkcs12 -export`) with 32-char password | `openssl version` |
| `certbot` | Let's Encrypt HTTP-01 issuance / renewal (`certonly --standalone` or `--webroot`) | `certbot --version` |

No Python packages to pip-install — stdlib only; system binaries via apt (below).

### Install on Debian / Kali / Ubuntu

```bash
sudo apt update
sudo apt install -y openssh-client openssl certbot
ssh -V
openssl version
certbot --version
```

### Install on other distros

```bash
# Fedora / RHEL
sudo dnf install -y openssh-clients openssl certbot

# Arch
sudo pacman -S --needed openssh openssl certbot

# macOS (Homebrew)
brew install openssh openssl certbot
```

### System & limitations

* **Linux:** Tested on Kali/Debian; other OSes remain untested (sudo/root model assumed).
* **Windows:** Run it in WSL2 (Kali/Ubuntu), ideally with mirrored networking (`.wslconfig`: `networkingMode=mirrored`) so the SNAT target and the TFTP callback reach the same IP.
* **Networking:** You must satisfy **both directions**: internet → you on TCP/80 through the SNAT (HTTP-01), and Firebox → you on UDP/69 (TFTP pull); Only works if both paths are arranged.
* **Binaries + root** (table above): `python3` (stdlib only), `ssh`, `openssl`, `certbot`. Issuance needs root (ports 80/69, `/etc/letsencrypt`); assess/show works unprivileged.
* **Accounts:** read-only `status` for assess/show; `admin` for import/select; only one admin in Edit Mode at a time.
* **Scope:** single-FQDN HTTP-01 only — no wildcards (those need DNS-01, unsupported). IPv4 only (TFTP server and LAN-IP detection are v4). Fireware 12.x (tested 12.12.3). CLI import takes Base-64 PEM only (`.pfx` via Web UI/WSM).
* **Firebox CLI idle timeout is short.** Keep the TUI moving; if the session drops mid-flow (`Command Line Timeout`), just reconnect and re-run — every step is re-runnable and idempotent.
* **Not yet automated (fail early, manually):** the tool does not pre-check that the domain resolves to the Firebox external IP, nor that TCP/80 is free locally — verify both before running, or certbot fails minutes in.

### Firebox SNAT for HTTP-01 (port 80) — required for issue/renew

Let's Encrypt HTTP-01 reaches `http://<domain>/.well-known/acme-challenge/...` on TCP/80 from the internet. The Firebox must forward that to the certbot host:

* **SNAT rule:** TCP/80 from `Any-External` to the Firebox external IP → SNAT to the certbot host.
* **Policy:** allow `HTTP` from `Any-External` to the SNAT action / certbot host.
* **DNS + test:** `<domain>` must resolve to the Firebox external IP; from outside the LAN, `curl -v http://<domain>/.well-known/acme-challenge/test` should get TCP/80 through.
* Keep the rule in place but consider disabling/enabling it for security — renewals need it again every 60–90 days. Remove it only if you switch to DNS-01 (not covered by this tool yet).
* Official example: Configure Static NAT to a Web Server - https://www.watchguard.com/help/docs/help-center/en-US/content/en-US/Fireware/configuration_examples/snat_web_server_config_example.html

### Notes

* `--standalone` needs TCP/80 free here (stop nginx/apache, or use `--webroot`) **and root**: run `sudo python3 acme.py --tui` for issuance/renewal; assess/show works unprivileged.
* **Firebox login: `status` to inspect, `admin` to import.** Steps [4/6] import and [6/6] select need **`admin`**.
* **Firebox CLI takes PEM only.** `import certificate general-usage from tftp://…` rejects `.pfx` bundles (`%Error: … must be a Base-64 encoded PEM file`, confirmed on 12.12.3) — the `.pfx` goes via Web UI (`System > Certificates > Import`) or WSM. A combined cert+key+chain PEM *is* accepted by the CLI.
* **Only one admin in Edit Mode.** If the box answers `%Error: … has selected Edit Mode`, another admin session holds the lock — have it type `exit` (back to View Mode) or disconnect, then re-run.
* **TFTP direction is Firebox → you.** The box pulls from this host, so UDP/69 must be reachable from the Firebox. No fetch seen? Troubleshoot while retrying the import:
  ```bash
  sudo tcpdump -nei any udp port 69   # watch for the RRQ from the Firebox
  sudo ss -ulnp | grep ':69'          # confirm the temporary server is listening
  ```
* Certificate files land in `output/certs/<domain>/`.
* The `.pfx` password is autogenerated (32 chars) and saved next to the bundle.

## Run

Two modes — same command, with or without root:

```bash
python3 acme.py
sudo python3 acme.py         # required for certbot (port 80), TFTP (port 69), /etc/letsencrypt
```

`-h` is host, not help, type `--help` for command usage

`--host/-h`, `--port/-p`, `--user/-u` override the defaults

`--showonly` just prints the web server certificate assessment and exits
